## Reading contract

This is the build-1 specification for Change `chg_012fffba-3604-48f8-b88f-62725bfd0cec`, Feature Request `frq_37c141636f684f60a2c72e52885d039b`. The boundary is what the registered PostgreSQL role is granted on the server. The plugin adds no read-only connection setting, no statement-leader allowlist and no confirmation step on top of those grants. The vendor surface here is the PostgreSQL 17 SQL command set, its system views and functions, and the client programs `pg_dump` and `pg_restore`.

The plugin has fourteen process definitions. The eight connector verbs that existed before this build are `list_connections`, `list_schemas`, `list_tables`, `describe_table`, `test_connection`, `run_query`, `export_query` and `run_statement`. Build 1 adds six family verbs: `run_script`, `copy`, `dump_database`, `restore_database`, `activity` and `statistics`. Every verb except `list_connections` is asynchronous. The dispatch returns a job id, and the result arrives when the job completes.

No family below is left without a path forward. “Generic path” means that any SQL the role is granted runs today through `run_statement` (one statement; `autocommit` for commands that cannot run inside a transaction block) or `run_script` (several statements in one transaction), and that the named build adds a typed verb. “No API” records a capability the vendor does not expose to a client connection, with the evidence.

## Build order

Build 1 (this change) covers transactions and scripts, COPY, dump and restore, and the activity, lock, statistics and size readers with their cancel, terminate and reset writes. It also removes the old read-only posture: no verb opens a read-only connection, and `run_query`/`export_query` no longer refuse a statement by its leading keyword.

Build 2 adds typed verbs for schema and table lifecycle, catalog readers, roles and grants, extensions and sequences, maintenance, databases and tablespaces, `pg_dumpall`, and `pg_restore` listing and conversion.

Build 3 adds routines and triggers, replication, settings, large objects, physical backup, and the held-session decision for `LISTEN`, advisory locks and two-phase commit.

## Shared behaviour of the build-1 verbs

- Every verb takes a registered connection name, never a DSN. The platform's own database instance is refused for every verb.
- File paths (`copy`, `dump_database`, `restore_database`) must be absolute and lie under an `export_allowed_roots` entry. The default empty list refuses every file operation until the operator adds a workspace directory.
- `pg_dump` and `pg_restore` are found in the `client_bin_dir` configuration directory, then on `PATH`, then in the standard Homebrew and Debian PostgreSQL directories. The password reaches them through a private, temporary password file that is deleted after the run, and never through the command line or the environment.
- Results are not scanned. The connector returns the vendor result as received; bulk results go to disk through `output_path`. Audit and log lines are built only from method, path without query values, status, duration and correlation id, so they never carry headers, bodies or credential values. A client program's stderr is returned with the host removed (topology-safe).
- `restore_database` never runs `psql`: plain SQL would need psql, whose backslash meta-commands run programs and read files on the Solet's host, where the vendor's grants do not apply. Restore takes pg_dump archives only, through `pg_restore`, which has no client-side commands; plain SQL runs through `run_script` (the driver, one transaction, a savepoint per statement). With `create`, the archive's own database name is checked against the platform database first.
- List operations take `limit` (1 to 1,000, default 100) and `offset`, and return `next_offset` when more rows exist.

## Reading contract

This is the first build-unit specification for Change `chg_e5fd0a15-b61d-4178-a188-130a7b97760b`, Feature Request `frq_8982f0c972bf4fab878f80b904f77b94`. The operator's boundary is the privilege granted to the registered Snowflake role. Build 2 (Change `chg_62448300-4048-404b-809c-2690acfd6da9`) added the typed SQL API, Task, Stream and Dynamic Table families. Build 3 (Change `chg_fb96bc89-811d-4931-9300-8d672604fbf0`) added the typed Database, Schema, Warehouse and Stage REST families. Build 4 (Change `chg_b6e07e57-9b9c-4a9a-a2a3-3c5b61c579fd`) added the typed Table, View, Sequence and Pipe REST families, the pipe family including Snowpipe file ingestion and load reports. The rows below record what each build covers and what the next build takes.

Build 5 (Change `chg_4297fdad-d824-46f8-b6c5-f2441efbad46`) adds the connector `stage_files` family.

The plugin has twenty-two process definitions. The connector verbs are `run_query`, `list_databases`, `list_schemas`, `list_tables`, `describe_table`, `export_query`, `test_connection`, and `run_statement`; `run_statement` forwards any one statement the role permits. The REST verbs are `request` (build 1, the generic authenticated path) and the typed families `sql_api`, `task`, `stream`, and `dynamic_table` (build 2) and `database`, `schema`, `warehouse`, and `stage` (build 3) and `table`, `view`, `sequence`, and `pipe` (build 4). `stage_files` (build 5) supplies local transfers and SQL COPY contracts. Each typed family is one verb with an `operation` parameter per documented endpoint, covering reads, writes, deletes, and actions alike. The plugin's async dispatch envelope is not the vendor operation's completion result.

Results are not scanned. The connector returns the vendor result as received;
bulk results go to disk through `output_path`. Audit and log lines are built
only from method, path without query values, status, duration and correlation
id, so they never carry headers, bodies or credential values.

No family below is left without a path forward. “Not wrapped” means that the next build unit must add a typed verb or use the single generic authenticated request path. “To verify” identifies a detail that must be checked against the named vendor reference before implementation, rather than inferred from a familiar endpoint shape.

## Read-only posture sites

The search `rg -n -i -e 'read[- ]only' -e 'read_leader' -e 'read-leader' -e 'no write' plugins/snowflake_plugin`, re-run for build 5, finds no posture site outside this article. Its one other match, `plugins/snowflake_plugin/src/snowflake_plugin/async_jobs.py` ("thread only"), is a regex false positive. The earlier sites were rewritten by commit `42d5dfee4`, which removed the read-only posture from the connector guidance. The remaining `read_only` mentions in `connection.py`, `async_jobs.py`, `01_snowflake_overview.md` and `smoke_async_jobs.py` describe the Postgres session flag that Snowflake lacks; they are not a restriction. Build 3 renamed the smokes' `EXAMPLE_READONLY` role fixture to `EXAMPLE_ROLE`. Vendor RBAC on the registered role is the only boundary for every verb.

## Build order

The order keeps writes and deletes first-class while preserving one generic long-tail path.

1. **SQL write and multi-statement contracts (M).** Add named smoke coverage for DELETE, DDL, `CALL`, `EXECUTE TASK`, `ALTER`, `USE`, and scratch-database multi-statement behavior. Keep `run_statement` single-statement unless the new script verb is deliberately selected.
2. **Stage files and copy operations (L).** Build 3 added the Stage REST family (`stage`: lifecycle, `list_files`, `presigned_url`). Build 5 adds `stage_files`: PUT/GET/LIST/REMOVE, COPY INTO table/location and COPY FILES, with absolute-path containment and an offline byte-equality round trip.
3. **SQL API (M).** Built in build 2 as `sql_api`: submit (including multi-statement), status with result partitions, and cancel over `/api/v2/statements`.
4. **Generic authenticated request (M).** Built in Unit `unt_a3f4337c-40d9-418d-8827-c5b150dd6458`: `request` supplies method/path/query/header/body, vendor status/body/pagination passthrough for the registered account, using its RSA key pair; vendor RBAC governs writes and deletes.
5. **Resource REST CRUD/actions (L).** Tasks, streams, and dynamic tables were built in build 2 as `task`, `stream`, and `dynamic_table`; databases, schemas, warehouses and stages in build 3 as `database`, `schema`, `warehouse`, and `stage`, each with deletes and actions. Build 4 added tables, views and sequences as `table`, `view` and `sequence`, and pipes with Snowpipe ingestion as `pipe` (step 6). The connector stage-file family (step 2) was added in build 5.
6. **Snowpipe and Snowpipe Streaming (L).** Snowpipe file ingestion, insert reports and load history were built in build 4 as `pipe`. Build 6 starts with Snowpipe Streaming: streaming hostname/tokens, row append, channel lifecycle, and delivery/readback smokes.
7. **Procedures, UDFs, Snowpark, and Cortex (L).** Add typed contracts only after response, package/runtime, streaming, and sensitivity semantics are verified against current vendor references; use the generic path for the remaining operations.
8. **Information Schema and account administration readers/writers (M/L).** Add convenience readers for stable high-value metadata and typed user/role/grant operations where authorization/audit contracts are explicit. Keep arbitrary metadata available through SQL query/export.
9. **Long-tail REST resources (M per family after generic path).** Use the single generic authenticated request verb until a family earns a typed contract; do not omit a family merely because it is not yet wrapped.

## Build 6 remainder

Build 5 completes the stage-file family only. In order: Snowpipe Streaming hostname/tokens/channel lifecycle/append/readback; then procedures, UDFs, Snowpark and Cortex after runtime/response/sensitivity verification; then event/Iceberg tables, external volumes, notebooks/Streamlit, compute pools, services, functions/procedures and the remaining REST families. Generic request availability is not typed coverage. No new SDK dependency was added.

## Acceptance mapping

| Acceptance clause | Mapping |
|---|---|
